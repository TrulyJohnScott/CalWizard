# Cal Wizard — Spec v3 (the contract)

> §1–§13 are v2 (curve, levels, ladder, experiments). §14–§21 are v3: what-if, limits, separation, requirements,
> read-back, reader import, report and the workspaces. §22 is the variability layers (lots, readers, days), §23 conditions, §24 fixed bias and the error budget. Where §21 and §11 disagree about the top bar or layout, §21 wins.

**Purpose:** help lateral flow assay developers see how mean signal and its variability together
determine their ability to resolve concentrations, and judge how good an assay is.

**v2 is a redesign driven by user feedback on v1:** v1 was "hideous and packed with garbage". v2 is
compact, quiet and minimal. **No log axes. No sliders.** Inputs are typed equations or tables, in a
compact input bar that can be hidden. Only what is needed is on screen.

v2 scope: one series. Conditions (comparing several series) come later — keep math/charts taking a
Series argument so that is additive. No hook effect.

```
calwizard/
  spec/SPEC.md                      ← this file (source of truth)
  spec/fixtures/model_vectors.json  ← generated by backend; frontend parity tests read it
  backend/   FastAPI + numpy/scipy/openpyxl, managed with uv (port 8000)
  frontend/  Vite + React + TypeScript + Plotly.js (port 5173, proxies /api → 8000)
```

## 1. Input modes (one active at a time, chosen by a selector)

| `mode`       | User enters                                                                  | mean(c)                          | sd at c                     |
|--------------|------------------------------------------------------------------------------|----------------------------------|-----------------------------|
| `equations`  | one-line `mean(c) = <expr in c>` and one-line `sd(S) = <expr in S>`          | expression                        | `sdExpr(S = mean(c))`       |
| `replicates` | a grid: each **column header is a concentration**, cells below are replicate signals | PCHIP through column means  | PCHIP through column SDs    |
| `summary`    | a table of rows `c, mean, sd`                                                | PCHIP through means               | PCHIP through sds           |

Note: in `equations` mode SD is a function of **signal** S, not concentration.

### Levels (anchors)
- Levels **always include 0** (the blank) and are sorted ascending, unique, ≥ 0.
- `equations`: levels come from a one-line field, e.g. `0, 1, 5, 25, 100, 500`. 0 is forced in.
- `replicates`: levels = column headers. The first column is fixed at c = 0 (header not editable).
- `summary`: levels = the rows' c. The first row is fixed at c = 0.

### Concentration range
`cMax` = largest level (table modes) or a user field defaulting to the largest level (equations).
All axes are **linear**, concentration from 0 to cMax.

## 2. Expression language (both sides implement the same tiny parser)

Grammar (recursive descent; whitespace ignored):
```
expr   := term (('+' | '-') term)*
term   := unary (('*' | '/') unary)*
unary  := ('-' | '+') unary | power
power  := atom ('^' unary)?            // right-associative; -2^2 = -4
atom   := number | ident | func '(' expr (',' expr)* ')' | '(' expr ')'
number := digits ['.' digits] [('e'|'E') ['+'|'-'] digits]   (also '.5')
```
- Variables: `c` in the mean expression; `S` (also accept `s`) in the sd expression. Constant `pi`.
- Functions (case-insensitive): `sqrt, exp, ln, log` (**log = base 10, like Excel**), `log10, abs, min, max`.
- Errors: unknown identifier, wrong variable for that field, bad syntax → error message with the
  character position. UI keeps the last valid expression while the user types.
- Evaluation: plain floats; NaN/±inf allowed and treated as invalid points.
- **Excel emission:** from the AST, fully parenthesised, with the variable replaced by a given cell
  reference: `sqrt→SQRT, exp→EXP, ln→LN, log→LOG10, log10→LOG10, abs→ABS, min→MIN, max→MAX, pi→PI()`,
  `^` stays `^`. Full parentheses avoid Excel's unary-minus precedence difference.

Presets (fill the text fields only; selectable from a small dropdown):
- mean: Linear `a + b*c`; Quadratic; Power `50 + 12*c^0.8`; Exponential; Log `50 + 900*ln(1 + c/20)`;
  4PL `4000 + (50 - 4000)/(1 + (c/40)^1.2)`; 5PL `4000 + (50 - 4000)/(1 + (c/40)^1.2)^0.8`.
- sd: Floor + CV `sqrt(15^2 + (0.08*S)^2)`; Constant `20`; CV only `0.08*S`; Power `2 + 0.05*S^1.1`.

Default series on first load: equations mode, mean = the 4PL preset, sd = Floor + CV preset,
levels `0, 1, 5, 25, 100, 500`, cMax = 500.

## 3. Table interpolation (both sides MUST match exactly)
- Points sorted by c; duplicate c averaged.
- PCHIP (Fritsch–Carlson, as `scipy.interpolate.PchipInterpolator`) on **linear c** through
  `(c_i, mean_i)` and separately `(c_i, sd_i)`. 1 point ⇒ constant; 2 points ⇒ linear.
- Below c_first: hold flat. Above c_last: the **mean continues as a straight line** with the PCHIP end
  slope (`d_n`, scipy's `derivative()(c_last)`; 2 points ⇒ the line continues); the **SD holds** its last value.
  So the curve can be measured and read past the highest concentration (v2.4).
- `replicates` mode: column mean and **sample SD (n−1)**; columns with < 2 numeric cells have no SD
  → that column is excluded from the SD interpolation (if none have SD, sd = 0 and the UI says so).

## 4. Series object (JSON shared by frontend & backend)

```json
{
  "name": "Example",
  "units": "ng/mL",
  "signalLabel": "Signal",
  "mode": "equations",
  "meanExpr": "4000 + (50 - 4000)/(1 + (c/40)^1.2)",
  "sdExpr": "sqrt(15^2 + (0.08*S)^2)",
  "levels": [0, 1, 5, 25, 100, 500],
  "cMax": 500,
  "extraLevels": [],
  "replicates": { "concs": [0, 1, 5], "cells": [[48.1, 52.0, 47.3], [55.0, 58.2, 53.9], [90.1, 101.3, 95.5]] },
  "summary": [ { "c": 0, "mean": 50, "sd": 15 }, { "c": 5, "mean": 95, "sd": 16 } ],
  "metric": "ssmd",
  "kTarget": 3,
  "sim": { "n": 5, "seed": 42 }
}
```
- `extraLevels` (v2.4): simulated concentrations added to a **table-mode** series (sorted, unique, finite, ≥ 0;
  ignored in equations mode, whose `levels` are all simulated). Table-mode levels = table concentrations ∪
  `extraLevels`; they get simulated dots (§7) drawn hollow, and take part in rows, ladder and measure like any level.
  Shift-click on the scatter adds one (equations mode: to `levels`), as one undoable step.
- `replicates.cells[j]` = list of replicate signals for column `concs[j]` (ragged allowed; nulls ignored).
- All three mode payloads are kept so switching modes never loses data. Only `mode` decides which is used.

## 5. Separation between adjacent levels

For adjacent levels `c1 < c2`: `μi = mean(ci)`, `σi = sd(ci)`, `Δμ = μ2 − μ1`.

| key      | Name        | Formula                    |
|----------|-------------|----------------------------|
| `dsum`   | Δμ / Σσ     | `Δμ / (σ1 + σ2)`           |
| `ssmd`   | SSMD        | `Δμ / sqrt(σ1² + σ2²)`     |
| `zprime` | Z′          | `1 − 3·(σ1 + σ2)/|Δμ|`     |
| `ovl`    | overlap     | `∫ min(p1, p2)`, trapezoid, 4001 points over [min(μ)−8·max(σ), max(μ)+8·max(σ)] |
| `err`    | misclassification | `0.5·(P(X1 > t) + P(X2 < t))` at the PDF crossing t between μ1 and μ2 (midpoint if equal σ / no root) |

Row = `c1, c2, mu1, mu2, sd1, sd2, dmu, dsum, ssmd, zprime, ovl, err, pass` where pass is
`|value| ≥ kTarget` for dsum/ssmd and `zprime ≥ kTarget` for Z′ (Z′ default target 0.5).
σ = 0 edge cases: return ±inf/NaN sensibly, never crash.

## 6. Inverse (signal → concentration)
Numeric: on [0, cMax], dense scan (2001 points) for a bracketing sign change of `mean(c) − S`,
then 60 bisections; first bracket from c = 0 wins. `null` if no bracket. Works for every mode.

## 7. Simulation
In `equations` and `summary` modes, replicates per level are simulated: `n` draws of
`Normal(mean(c), sd(c))` with seeded PRNG (frontend: mulberry32 + Box–Muller). In `replicates` mode
the entered data are the dots; nothing is simulated.

## 8. Fitting (backend `/api/fit`)
Input: points `[{c, y}]` (from replicates) or summary rows (mean with n=1, sd given).
Fits mean models: linear, quadratic, power, exponential, log, 4PL, 5PL (robust initial guesses,
bounds, multi-start), ranked by AICc. Fits sd-vs-signal models: floor+CV, constant, CV-only, power.
Each fit returns `{kind, params, expr, r2, aicc, ok}` where **`expr` is a ready-to-use expression
string in the §2 language** (numbers rounded to 4 significant digits). Never HTTP-errors on bad data.

## 10. Excel export
1. **Inputs** — mode, units, labels, cMax, kTarget, metric. In equations mode the two expression
   strings as text (for reference). In table modes the table as entered.
2. **Calculator** — input cell `c` → live `mean(c)` and `sd(c)`; input cell `S` → `c(S)`.
   - equations: `mean` = emitted Excel formula of meanExpr with `c` → the input cell;
     `sd` = emitted formula of sdExpr with `S` → the mean cell. **Editing the formulas in Excel is
     the way to change the model.**
   - table modes: forward = linear interpolation (INDEX/MATCH/FORECAST) on the dense **Grid** sheet.
   - reverse (all modes): interpolation of c against the Grid's mean column (assumes monotone; returns
     "out of range" outside).
3. **Grid** — 501 points c from 0 to cMax with mean and sd (live formulas in equations mode,
   values in table modes).
4. **Levels** — adjacent-pair table with live formulas for Δμ, Δμ/Σσ, SSMD, Z′ and err (NORM.DIST);
   ovl as a value.
5. **Data** — replicates grid (concentrations across the top, as entered) and per-level mean/SD/n/CV.
6. A native Excel scatter chart of mean(c) on the Grid sheet (linear axes).

## 11. Frontend UX (v2)

**Overall:** quiet, compact, generous whitespace, nothing decorative. Neutral greys + one accent.
13px base type, tabular numerals. Light and dark. No explanatory paragraphs; at most a `title`
tooltip on a header. No cards-within-cards, no badges, no colourbars unless the heat cloud is on.

**Screen layout (user-specified, overrides anything below that conflicts):**
```
┌ top bar ───────────────────────────────────────────────────────────────┐
│ LEFT PANEL      │        CENTRE (≈ half the width)        │ RIGHT SIDEBAR │
│ define the      │  scatter / calibration plot  (≈ 2/3 h)  │ separability  │
│ functions       │─────────────────────────────────────────│ by points:    │
│ (input modes)   │  histogram / Gaussians      (≈ 1/3 h)   │ levels list,  │
│ collapsible     │  same width, directly under, aligned    │ ladder,       │
│                 │                                          │ measure       │
└─────────────────┴──────────────────────────────────────────┴───────────────┘
```
- **Left panel** (~300px, collapsible to a thin rail) holds what the "Input drawer" below describes:
  mode selector + the active editor + levels/cMax for equations. There is no top drawer.
- **Centre**: calibration scatter on top, histogram below at half its height, same width, plot areas
  left-aligned so the axes line up. No View toggle — both are always shown.
- **Linked**: the histogram's signal axis uses the same range as the scatter's signal axis; when the
  scatter is flipped (`S → c`, x = signal) the two share the x axis exactly (zoom/pan linked).
  Hovering the scatter shows a live dashed "probe" Gaussian at the hovered concentration in the
  histogram, so moving the mouse along the curve visibly slides/widens the distribution.
- **Right sidebar** (~280px, collapsible): the Levels sidebar (§11 item 3) — separability by points.

**Three ways to define the curve (v4) — supersedes v2.9's two views:** the left panel's `Data | Stats | Function`
switch picks the view; the curve has one *source* (`mode`: `replicates` = Data, `summary` = Stats, `equations` =
Function). Data is the replicate grid (concentrations across, readings below, mean and SD computed); Stats is one row
per concentration with its mean signal and SD (a spare last row adds one; clearing a concentration removes it);
Function is signal(c) and σ(signal) as formulas. Every view shows the current curve; editing in a view makes it the
source (one undo step). A marker says "● these … define the curve" or "○ shown from the current curve · editing here
makes it define the curve". Quick entry and "fill with simulated readings" are gone.
- Equations view while the table drives: the best fits of μ(c) and σ(S) (§8, refitted 400 ms after any table change)
  shown as editable formulas, plus the other ranked fits (hover previews dashed on the chart). Editing a formula,
  picking a fit, or **Drive from these fits** makes the equations drive (keeping the table's levels and range),
  as one undo step.
- Table view while the equations drive: the equations' mean and SD at each level, live. Editing any cell (or quick
  entry) makes the table drive, as one undo step; "fill with simulated readings (n)" does so with simulated replicates.
- `Equations → Table` and `Table → Equations` buttons are gone. Headless: `calwizard fit` gives the same fits.

**Unified Table + two-way sync (v2.2) — supersedes the Replicates and Mean & SD editors:**
- Left-panel selector becomes `Equations | Table` (the `replicates`/`summary` payloads stay in the
  Series for compatibility; Table writes `replicates`, and mean/sd typed without replicates go to `summary`).
- **Table** = one Excel-like grid (Glide Data Grid, `@glideapps/glide-data-grid`): **concentrations
  across the top** (header row, first fixed at 0), replicate signals underneath, and two muted rows
  at the bottom: `mean` and `sd`. They are computed from the replicates; if a column has no replicates
  the user types mean and sd there directly. Click-and-type, Tab/Enter/arrows, drag-select, Delete
  clears, Ctrl+C/Ctrl+V blocks to/from Excel, typing into the empty edge column/row grows the table.
  No +/× buttons. The left panel widens (to ~60% of the window, overlaying the centre) while the grid
  has focus and returns when it loses focus / Esc.
- **Two-way sync:** `Table → Equations` (fit, existing ranked list, click to use) and
  `Equations → Table` (fills the header with the current levels and the mean/sd rows from the
  equations; optional "with n simulated replicates" using the sim n/seed). Both are single small
  buttons between the two views. Whichever view is selected is the source for the charts.

**Drag levels + closeness heat (v2.1):**
- **Drag:** each level marker on the scatter can be dragged along the curve (pointer-down within ~8px
  of a marker; `c → S`: horizontal movement sets c, `S → c`: vertical). Each Gaussian's peak in the
  histogram can be dragged horizontally (signal → c via the inverse). Level 0 is fixed. Dragging
  updates everything live (rAF-throttled) and commits on release; a level cannot pass its neighbours.
  Pointer-down elsewhere keeps the existing behaviours (click = measure, drag = zoom). Cursor shows
  `ew-resize`/`ns-resize` over a draggable marker. Table modes: drag is disabled (levels come from
  the table).
- **Heat = closeness of adjacent levels**, from the selected metric relative to its target:
  `q = |value| / kTarget` for Δμ/Σσ and SSMD; for Z′ use the equivalent `q = dsum / (3 / (1 − kTarget))`.
  Colour ramp: `q ≤ 0.25` deep fiery red → `q = 0.6` orange → `q → 1⁻` yellow; at `q ≥ 1` (resolved)
  cool blue, fading to fully clear by `q ≥ 2`. One shared function `closenessColor(q) → rgba`.
- **Where it shows** (and nowhere else):
  1. Scatter: the band segment between each adjacent pair of levels (concentration span c_i…c_{i+1},
     ±2 SD vertically) is filled with that pair's heat colour (replaces the neutral band there).
  2. Histogram: the overlap region of each adjacent pair (min of the two Gaussians) is filled with the
     pair's heat colour; clear pairs show no fill.
  3. Levels sidebar: each row gets a subtle heat-tinted left bar / background.

**Top bar (one line):** app name · series name (inline editable) · units · **Input** button (toggles
the input drawer) · Flip axes button (`c → S` / `S → c`) · small Settings (gear) popover · Export.

**Trust (v2.3) — supersedes conflicting lines above:**
- **Headline, always visible in the top bar** (even with both side panels hidden): `N resolvable levels`,
  where N = `len(ladder(metric, k, 0, cMax, sig = 4))` (§12), recomputed live whenever the curves, cMax,
  metric or k change (not when only the levels list changes). Hover lists the ladder; click applies it
  (same as the sidebar's Ladder button).
- **Pass rule chip** next to it, in plain words: `SSMD ≥ 3 · 1.7% misread` (the §12 rule error). Clicking it
  opens a small popover holding the metric selector, target k and an **Allowed error %** field; editing
  either number updates the other (§12). One sentence explains the rule. Metric and k leave the gear.
- **Undo / redo** for every change to the series (equations, table, levels, mode, fits, ladder, Load JSON):
  `Ctrl+Z`, `Ctrl+Shift+Z` / `Ctrl+Y` (ignored while a text field or the grid editor has focus, where the
  native text undo applies), and two small ↶ ↷ buttons in the top bar. Bursts of the same kind of edit
  within 1 s (typing a name, dragging a level) are one step. 100 steps; undo clears the ladder list, the
  measurement and the zoom. UI preferences are not part of history. Undo is GUI-only by nature: the
  headless surfaces are stateless (Series in, JSON out).
- **Destructive one-click actions** (Ladder, Load JSON, Equations → Table, picking a fit, removing a level)
  show a toast at the bottom centre: `<what happened> · Undo` for 6 s. No confirmation dialogs.

**Chart (v2.4) — supersedes conflicting lines elsewhere in §11:**
- **Gaussians are true densities** everywhere (histogram and side strip): equal area, height ∝ 1/σ, so a tight
  level is tall and narrow and a noisy one low and wide; the tallest drawn level peaks at the top. Overlap
  fills are the min of the two densities. Overlap % labels float above the overlap in a small boxed label
  with a hairline leader, never on the curve lines.
- **Distribution view (v2.8):** the panel under the scatter shows one set at a time: **Levels** (tested / table levels,
  overlaps) or **Anchors** (placed or auto-spaced points, blank first, overlaps with % labels). A
  `Levels | Anchors` switch (top left) appears while anchors exist; placing anchors flips to Anchors, clearing flips
  back. **Auto-space** and **Clear** sit on the chart toolbar (next to Read signal), not in the sidebar.
- **The spread (v4) — supersedes v2.7's background colour and shading modes:** the mean curve, and ±1σ, ±2σ, ±3σ
  as thinner, fainter lines in the curve's colour (widths 1.2 / 0.9 / 0.7 px, opacity 0.6 / 0.38 / 0.22). No haze,
  wash or heat map. **Colour** stays only on the foreground: ruler brackets and sidebar rows show the closeness of
  that specific pair.
- **Double-click resets the view** to the ranges computed from the current data (whole `[0, cMax]`, signal
  range per §11) on both charts — never to a range remembered from an earlier series. Plotly's own
  double-click reset is off.
- **Measuring never changes the levels.** Click a point, then a second (live readout while choosing): the pair
  is drawn as a ruler — two open handles on the curve joined by a bracket coloured by closeness, labelled
  `<metric> <value>` at its middle. Both handles can be dragged along the curve (the readout follows live).
  The sidebar readout has **Keep as levels** (equations mode only; one undoable step + toast), which adds the
  two concentrations to the levels. Esc or × clears the ruler. Measurements are not undo history.
- **Gaussians on the curve** (replaces the side strip, which would break the shared x axis): each level's signal
  distribution is drawn sideways at its concentration, on the curve's own signal axis, extending toward higher c:
  true density (the tightest drawn level spans 7% of the concentration axis, others narrower in proportion to
  σ_ref/σ), level colours, drawn out to ±3.5σ with small dots marking ±1σ (hover: the ±1σ range and SD).
  **Unit rulers** run from each level's and each anchor's centre along its signal height: tick j (1…5) at the smallest
  c above it whose separation from it is j target units, i.e. closeness q = j (dsum/ssmd: |value| = j·k; Z′: |dsum| =
  j·3/(1 − k); none when k ≥ 1). Each further segment fainter; anchors drawn darker than levels.
- **Anchors (N-point ruler, v2.6):** each click places an anchor on the curve (snapping to levels/ladder ticks; Alt =
  free); any number. Pressing a placed anchor selects it (ring) and dragging moves it; Delete/Backspace removes the
  selected anchor (else the last placed); Esc deselects, a second Esc clears all. The blank (c = 0) is always the first anchor, so the
  separation from 0 to the first placed point is shown too. The sidebar's ↶ and × do the same as Delete and Esc. **Auto-space** replaces the anchors from the selected one (else 0) upward
  with the §12 ladder (sig 4) from there to cMax, keeping anchors below the start; levels are not changed. Every adjacent pair of anchors shows a bracket coloured by
  closeness with its metric value; the sidebar lists each pair (metric, overlap, misread, steps between); the
  histogram emphasises the anchors and fills their adjacent overlaps. While only one anchor is placed the next is
  previewed live under the mouse. Anchors are independent of the tested concentrations and of the curve's source
  (equations or table); **Keep as levels** adds them all (one undo step). Headless: `calwizard measure SERIES C1 C2
  [C3…]` / `POST /api/measure {series, concs}` → `pairs` (each §5 row + `stepsBetween` + `whyNot`). Hovering draws a dashed one at the hovered concentration plus dotted guide lines
  from the concentration axis up to the curve and from the signal axis across to it. Gear `Gaussians on curve
  On | Off` (default On); works in both orientations.
- **Shared x axis.** The histogram below always shares the scatter's x axis (range, zoom, pan, plot edges): in
  c → S it shows each level's **read-back concentration** density, `φ((mean(x) − μ)/σ)/σ · |mean′(x)|` (true
  density, the overlap % is unchanged by the transform); in S → c it shows the signal densities. The orientation
  switch `c → S | S → c` sits on the chart (top right) next to **Read signal**.
- **Zoom** (the separate zoom strip is parked): box-zoom or pan the concentration axis to set the focus window;
  it may extend past cMax (the curve continues, §3). `Show all` or double-click returns to the whole range.
- **Shift-click** on the scatter adds a simulated concentration there (§4 `extraLevels` in table modes).

**Main area** (charts fill the width; everything below the top bar/drawer):
1. **Calibration chart** — linear axes. `c → S`: x = concentration 0…cMax, y = signal.

   first positive level.
2. **Histogram view (distributions & overlap)** — a first-class view. Top bar gets a small

   active, its two Gaussians are emphasised (others dimmed) and their overlap shaded. In `S → c` the
   panel stays in signal units (it is the signal-space view of separation).
3. **Levels sidebar** (right side, collapsible, narrow ~260px) — replaces a separate separation table.
   - An editable **list of concentrations** (the levels; first row fixed at 0). Type a value + Enter

## 12. Ladder, measure and closeness

Implemented in `backend/app/analysis.py` and `frontend/src/math/{analysis,closeness}.ts`; parity-tested via
`spec/fixtures/model_vectors.json` (`ladder`, `measure` per case). All are pure functions of a compiled model.

**Pair (measure).** `pair(c1, c2, metric, k)` = the §5 row with `μ = mean(c)`, `σ = sd(c)` evaluated at the two
concentrations, in the order given. `stepsBetween` = `len(ladder(from = min(c1,c2), to = max(c1,c2), sig = 0)) − 1`.
The ladder's default stop is the top of the usable range: a hook's peak (§15.4), else cMax.

**Pass.** `passes(metric, v, k)`: NaN never passes; `zprime` passes on `v ≥ k`, `dsum`/`ssmd` on `|v| ≥ k`.
`±inf` (σ = 0 with Δμ ≠ 0) passes, since `|inf| ≥ k`. (The TypeScript `passes` currently rejects every non-finite
value, so it differs for σ = 0 curves only; the intent is the rule above.)

**Ladder.** `ladder(metric, k, start = 0, stop = cMax, sig = 4)` returns `[start, c_1, c_2, …]`. With `a` the last level:
1. stop if `a ≥ stop` or 200 levels exist;
2. scan `c_j = a + (stop − a)·j / 2000`, `j = 1…2000`; the pair `(a, c_j)` is tested with the metric value only (no
   overlap integral); the first passing `c_j` is the bracket's right end, the previous scan point (or `a` for
   `j = 1`) its left end; if none passes, stop;
3. 60 bisections (`mid = (lo + hi)/2`; passes → `hi = mid`, else `lo = mid`); the level is `hi`;
4. if `sig > 0`: `p = 10^(sig − 1 − floor(log10 hi))`, `up = ceil(hi·p − 1e-9)/p`; use `up` instead of `hi` when
   `up ≤ stop` and `(a, up)` passes (the GUI Ladder button and the API default use `sig = 4`; `sig = 0` = raw);
5. append, then repeat. The headline "N resolvable levels" is `len(levels)`.

**Closeness.** `closenessQ(row, metric, k)` (`q < 1` unresolved, `q ≥ 1` resolved; NaN → 0):
`dsum`/`ssmd`: `|row[metric]| / k` (2 if `k ≤ 0`); `zprime` with `k < 1`: `|row.dsum| / (3 / (1 − k))`;
`zprime` with `k ≥ 1`: 2 if `row.zprime ≥ k` else 0.

**Pass rule in plain words.** For two Gaussians with equal SDs σ and means Δ apart, the misclassification
rate at the midpoint threshold (§5 `err`) is `Φ(−Δ/2σ) = Φ(−dsum)`. So every (metric, k) has one error rate:
- `dsum`: `err = Φ(−k)`; `ssmd`: `err = Φ(−k/√2)` (both: `k ≤ 0` → 0.5);
- `zprime`: `k < 1` → `err = Φ(−3/(1 − k))`; `k ≥ 1` → 0 (only σ = 0 reaches it).

`ruleError(metric, k)` returns that number and `kForError(metric, e)` inverts it for `0 < e < 0.5`
(`z = Φ⁻¹(1 − e)`: `dsum` → `z`, `ssmd` → `√2·z`, `zprime` → `1 − 3/z`); `e` outside (0, 0.5) is an error.
Text: `<metric label> ≥ <k> · <err as %> misread`, with the % to 2 significant digits (`< 0.0001%` below
1e-6). It is exact only for equal SDs, which the explainer sentence says.

**Recovery (v2.4).** `recover(S, conf = 0.95)` reads a signal back to concentration: `c = inverse(S)` (§6), and the
range = hull of `{c ∈ [0, cMax] : |S − mean(c)| ≤ z·sd(c)}`, `z = Φ⁻¹(1 − (1 − conf)/2)` — the concentrations whose
single-reading spread covers S (classical inverse-prediction interval). 2001-point scan `c_j = cMax·j/2000`, then 60
bisections at each end (outside ↔ inside). `loOpen` = range touches 0 (zero cannot be excluded: at or below the
detection limit), `hiOpen` = touches cMax. No scan point inside → `lo = hi = null`. Row:
`{signal, c, lo, hi, loOpen, hiOpen, conf, hook}`. With a high-dose hook (§15.4) the scan covers [0, peak] and
`hook` is true when the signal is also within z·sd of the curve above the peak (the reading is ambiguous). GUI: **Read signal** button on the scatter places a draggable signal line
(horizontal in c → S, vertical in S → c); it shows `S → c (lo–hi)` on the chart, marks c on the curve and shades lo–hi
on the concentration axis. Not undo history; × or Esc removes it.

**Why not resolved (v2.5).** `whyNot(c1, c2, metric, k)` → `{needDmu, dmu, sdScale, moveTo}`: `needDmu` = the |Δμ|
the pair needs at its current SDs (`dsum`: k(σ₁+σ₂); `ssmd`: k√(σ₁²+σ₂²); `zprime`: 3(σ₁+σ₂)/(1−k), null if k ≥ 1;
floored at 0); `sdScale` = the factor both SDs must be multiplied by at the current Δμ (= closeness q; null if not
positive/finite); `moveTo` = `ladder(start = c1, sig = 0)[1]` (null if nothing passes up to cMax). The sidebar shows it
under each failing row: `needs Δμ ≥ 14 (has 6.6) · or SD ×0.65 · or 5 → 6.8`.

**HTTP and CLI** (both JSON in/out; `metric`/`k` default to the series' `metric`/`kTarget`):
- `POST /api/ladder {series, metric?, k?, start?, stop?, sig?}` → `{levels, n}`
- `POST /api/measure {series, c1, c2, metric?, k?}` → §5 row + `stepsBetween` + `whyNot`
- `POST /api/recover {series, signals, conf?}` → `{rows}` (422 if conf ∉ (0, 1))
- `POST /api/rule {metric, k}` or `{metric, error}` → `{metric, k, error, text}` (422 if error ∉ (0, 0.5))
- `POST /api/evaluate` and `calwizard evaluate` also return `resolvable` (`{levels, n}`, the headline ladder)
  and `rule` (as above, for the series' metric and kTarget)
- `calwizard evaluate|ladder|measure|recover|rule|inverse|fit|export|parse` — see AGENTS.md; errors are JSON on stderr, exit 1
  (invalid expression/model) or 2 (bad input).

## 13. Simulated experiments (v2.5)

Purpose: the left side defines the **truth** (curves); an **experiment** draws `n` readings per concentration from it
and measures separation from those readings, as a real lab would. Re-rolling shows what one experiment could show;
many runs show the range of outcomes. With `n` set to the counts actually measured in a table, the same engine
answers "what ranges could our data have produced?" (a parametric bootstrap of the fitted truth).

**Random numbers (both languages, bit-for-bit order).** `mulberry32(seed)` exactly as `frontend/src/math/sim.ts`
(uint32 state; `a += 0x6D2B79F5`; `t = imul(a ^ a>>>15, a | 1)`; `t ^= t + imul(t ^ t>>>7, t | 61)`;
`u = (t ^ t>>>14) >>> 0) / 2^32`). One standard normal = Box–Muller on two consecutive draws:
`z = sqrt(−2 ln max(u1, 1e−300)) · cos(2π u2)` (the sine value is discarded). Draw order: for run `r = 0…R−1`,
for each concentration in order, for `i = 0…n_c−1`: `y = mean(c) + sd(c)·z`.

**Inputs.** `simulate(model, concs?, n = 4, runs = 200, seed = 1, metric?, k?, conf = 0.9)`. `concs` defaults to the
model levels (sorted unique, ≥ 0); `n` is one integer for all or one per concentration (each ≥ 2, ≤ 1000);
`runs` 1…5000; `metric`/`k` default to the series'; `conf` ∈ (0, 1).

**One run.** Per concentration: `mean` = average of its `n_c` readings, `sd` = sample SD (n−1). Adjacent pairs
`(c_i, c_{i+1})`: the §5 metric values `dsum`, `ssmd`, `zprime` from those estimates and `pass` (§12 `passes`).
`resolvedPairs` = number of passing adjacent pairs.

**Output.**
- `concs`, `n` (per concentration), `runs`, `seed`, `metric`, `k`, `conf`;
- `truth`: `{rows: [{c1, c2, value, pass}], resolvedPairs}` from the true means/SDs (value = the chosen metric);
- `first`: run 0 in full: `{levels: [{c, ys, mean, sd}], rows: [{c1, c2, dsum, ssmd, zprime, value, pass}], resolvedPairs}`;
- `levels`: per concentration over all runs `{c, mean: Q, sd: Q}`;
- `pairs`: per adjacent pair `{c1, c2, truth, Q…, pPass}` where `Q = {lo, med, hi, min, max}` of the run values of
  the chosen metric and `pPass` = fraction of runs passing;
- `resolvedPairs`: `{Q…, hist}` with `hist[j]` = runs with exactly `j` passing pairs (`j = 0…pairs`);
- `pAllPass` = fraction of runs where every adjacent pair passes.
- **Power (v2.8):** each run also tests each adjacent pair with a two-sided **Welch t-test** on its readings (means,
  sample SDs, n per side; df by Welch–Satterthwaite; both SDs 0 → p = 0 if the means differ, else 1). `first.rows[i].p`
  = run 0's p-value; `pairs[i].pSig` = fraction of runs with p < `alpha` (default 0.05; output `alpha`). In words: "run
  these concentrations with n each and you see a statistically significant difference pSig of the time".

`Q` quantiles use linear interpolation between order statistics (numpy `linear`, i.e. position `p·(R−1)`):
`lo` at `(1 − conf)/2`, `med` at 0.5, `hi` at `1 − (1 − conf)/2`. NaN values (e.g. Z′ with Δμ = 0) count as not
passing and are excluded from `Q` (all NaN → `Q` fields null).

**Headless.** `calwizard simulate SERIES [--concs C...] [--n N | --n-per N...] [--runs R] [--seed S] [--metric M]
[--k K] [--conf P] [--measured-n]` (`--measured-n`: table modes, n = each column's count of readings); JSON out.
`POST /api/simulate {series, concs?, n?, runs?, seed?, metric?, k?, conf?, measuredN?}` → the output above.
Parity: `spec/fixtures/model_vectors.json` → `simulate` entries (a few cases, exact draws compared at rel 1e-9).

**GUI.** Right sidebar header gets `Levels | Experiment`. Experiment shows: `n` per level (number field; in table
modes a `as measured` toggle), **Re-roll** (seed + 1) and the run count (`1 · 200 · 1000`); a one-line headline
`resolved pairs: truth 4 · this run 3 · 90% of runs 2–5 · all pass 41%`; per pair a row with the true value, this
run's value, a horizontal 90% range bar with the truth tick and this run's dot, coloured by closeness, `signif.`
(pSig) and `target` (pPass). It opens with one sentence: "If you ran these N concentrations with n = … each, neighbours
would differ significantly (p < 0.05) in X–Y% of experiments." (≥ 80% power shown in the accent colour.)
The scatter shows this run's readings as dots (replacing the simulated dots) and each level's estimated mean as a
short dash. Experiment state (n, runs, seed, open) is UI state, not undo history; it is never saved into the Series.

## 14. What-if layer (`adjust`)

A layer on top of the curve, whatever its source (equations or table): four levers that match bench work.
`adjust = { bottom, top, cScale, sdScale }` (`null`/`null`/`1`/`1` = unchanged; `adjust: null` = no layer).

With `f`, `g` the unadjusted mean and SD, `B = f(0)`, `T = f(cMax)`, `B' = bottom ?? B`, `T' = top ?? T`,
`gain = (T' − B')/(T − B)` (1 when `T = B`), `xs = cScale`:

- `mean'(c) = B' + (f(c/xs) − B)·gain` — background and top move the two ends, `cScale` stretches the concentration axis
  (`< 1`: the curve responds at lower concentrations);
- equations: `sd'(c) = sdScale · sdExpr(mean'(c))` (the noise model follows the new signal);
  tables: `sd'(c) = sdScale · g(c/xs)`.

`cMax` and the levels do not change. Everything downstream (rows, ladder, limits, read-back, export) uses the adjusted
curve. Validation: `cScale > 0`, `sdScale ≥ 0`, both finite.

**Bake.** `bake(series)` returns the same curve with the layer folded into the source and `adjust: null`: equations get
`(B') + (f(c/(xs)) − (B))·(gain)` and `(sdScale)·(sdExpr)` as fully parenthesised expression text; tables get
`c → c·xs`, each reading `y → y(mean) + (y − mean)·sdScale` with `y(v) = B' + (v − B)·gain`, typed rows likewise. It is exact
(PCHIP is affine-equivariant). Excel export bakes first. Headless: `calwizard bake SERIES`, `POST /api/bake`.

**GUI.** `What if` in the top bar (key `W`) shows a bar with four scrub fields (type, arrow keys, or drag the label;
no slider track) and, while a layer is active, the change in the headline claims (`levels 8 → 22 · LoD 4.62 → 1.56`),
`Reset` and `Keep as the curve` (bake, one undo step). On the Curve chart four diamonds are draggable: background and
top (along the signal axis), midpoint (along the concentration axis), noise (the +2σ band edge at 0.72·cMax). During a drag
the signal range is held still and every move is measured from the drag's starting state, so the chart never rescales
under the cursor. The unadjusted curve stays visible as a dashed line. Levels are not draggable while the diamonds are out.

## 15. Limits: LoB, LoD, LoQ (CLSI EP17 style)

`limits(model, alpha = 0.05, beta = 0.05, cv = 0.2, reads = 1)`; `sd_r(c)` = SD of one result, the mean of `reads`
readings of a sample: `√(within(c)/reads + Σ layer terms(c))` with the §22.1 terms (without layers `sd(c)/√reads`). Only
within-run noise averages; lot, reader, day and the other layer terms are shared by the reads. Direction `d` = the sign
of the largest excursion `mean(c) − mean(0)` on a 2001-point grid over [0, cMax] (`−1` for competitive assays; robust to
a hook or a fit that dips at the far end); `z_a = Φ⁻¹(1 − alpha)`, `z_b = Φ⁻¹(1 − beta)`. All limits are searched on
[0, top], `top` = the hook's peak (§15.4) or cMax.

- **LoB** (signal) `= mean(0) + d·z_a·sd_r(0)`; as a concentration: the smallest c with `d·(mean(c) − LoB) ≥ 0`.
- **LoD** = smallest c in [0, cMax] with `d·(mean(c) − LoB) − z_b·sd_r(c) ≥ 0`.
- **Concentration CV** `cv(c) = sd_r(c) / (|slope(c)|·c)`, `slope` by a central difference with step `1e-4·cMax`
  (one-sided at 0); ∞ at c = 0 or where the curve is flat.
- **LoQ** = smallest c in [LoD, cMax] with `cv(c) ≤ cv`; **upper LoQ** = largest c in [LoQ, cMax] with `cv(c) ≤ cv`.
- "Smallest / largest c": 2001-point scan `lo + (hi − lo)·j/2000`, then 60 bisections between the last failing and the
  first passing point. `null` when nothing passes.
- `profile`: 201 points over [0, cMax]: `c`, `cv`, `cvSignal = sd_r/|mean|`.

Output: `{alpha, beta, cv, reads, direction, blank: {mean, sd}, lob: {signal, c}, lod, loq, uloq: {c, signal, cv} | null,
uloqOpen, hook, profile}`. `uloqOpen`: the CV is still within target at `top` (the end of the data or of the range), so
the true upper limit lies beyond it; shown as "≥".

**15.4 High-dose hook.** `hook` = `{c, signal}` of the peak of `d·mean(c)` when it lies inside [0, cMax] and the signal
turns back after it by more than 1e-6 of the signal span (2001-point scan, then 60 golden-section steps), else null.
Above the peak a signal is also produced by a lower concentration, so every claim stops there: limits, the ladder (§12),
range requirements (§17) and read-back (§18 flag `hook`).

**From replicates (`data`).** For a replicates series with a blank column and at least one c > 0 column of ≥ 2 readings:
LoB `= mean_b + d·z_a/(1 − 1/(4(n_b − 1)))·sd_b`, plus the nonparametric rank percentile (rank `0.5 + n·p`, linear
between ranks); LoD signal `= LoB + d·z_b/(1 − 1/(4·df))·SD_L` with `SD_L` the pooled SD of the low columns (default:
the two lowest), `df = Σ(n_i − 1)`; both read back to concentration with §6. `null` otherwise, and while a what-if layer
is active.

**Planner.** `plan(model, nBlank = 20, nLow = 20, low = [LoD, 2·LoD] to 3 s.f., runs = 500, seed, alpha, beta, conf = 0.9)`
simulates that experiment `runs` times with the §13 random stream (per run: blanks, then each low level, then the LoQ
sample) and applies the classical estimate to each: `{design: {rows, strips}, truth, lobSignal: Q, lodSignal: Q, lod: Q, lodFound, detect:
[{c, truth, mean}], first}`. It answers "with this many strips, how close would my LoD estimate land?". When the curve has a LoQ at `cv`
(default `limits.cv`), a sample at the LoQ (3 s.f.) is read `nLow` times as well: `loq = {c, n, cvTarget, cvTruth,
cv: Q, pPass}`, where a run's measured result CV is its signal SD over `|slope|·c` and `pPass` is the share of runs
with that CV within the target (near 50% for a sample exactly at the LoQ: claim a little higher to confirm reliably).

Headless: `calwizard limits SERIES [--alpha --beta --cv --reads --low C... --no-profile]`, `calwizard plan SERIES
[--n-blank --n-low --low C... --runs --seed --conf --cv]`; `POST /api/limits`, `POST /api/plan`.

## 16. Separation of two concentrations

`separate(model, c1, c2, metric, k, n = 3, runs = 1000, seed = 1, conf = 0.95, alpha = 0.05)` = the §5 row plus:
`threshold` (PDF crossing between the means; midpoint for equal SDs). Positive = the higher concentration's side of
the threshold (above it on a rising curve, below it on a falling one): `sensitivity` = P(the higher concentration called
positive), `specificity` = P(the lower one called negative). With `threshold = T` the output also has
`at = {threshold, sensitivity, specificity}` at that fixed threshold (the shipped cut-off while the curve changes; the GUI
passes the measured curve's threshold while a what-if is on); `--threshold T` on the CLI. Also `auc = Φ(|Δμ|/√(σ₁² + σ₂²))`, `dprime = |Δμ|/√((σ₁² + σ₂²)/2)`, `cv1`, `cv2`, `fold = c2/c1`,
`closeness` q (§12), `nNeeded = ⌈1/q²⌉` (readings to average per sample for the pair to pass; null if unreachable),
`stepsBetween`, `whyNot`, `readback` (§12 recover of each mean) and `power` (§13 simulate on the two concentrations with
`n` each: `pSig`, `pPass`). Headless: `calwizard separate SERIES C1 C2 [...]`, `POST /api/separate`.

## 17. Requirements

`requirements: [{kind, c?, c2?, cv?, n?, label?}]`, checked by `check(model)` → `{results, met, total}`:

| kind | sentence | met when | value |
|---|---|---|---|
| `detect` | Detect c | LoD ≤ c | LoD |
| `distinguish` | Tell c from c2 | the pair passes the series' rule (SDs of one result, §15 `sd_r`) | metric value |

(40 bisections; null if even ×0.01 does not) — "met if the noise were 0.4× of today". Invalid rows come back with
`error`, never an exception. Headless: `calwizard requirements SERIES`, `POST /api/requirements`.

## 19. Reader import

`parse_reader(text, conc?, signal?)` turns a delimited reader export into a replicate table: delimiter = the one of
tab, `;`, `,` that splits the most lines into the same number (≥ 2) of fields (ties in that order), so a stray `;` in a
preamble or comma decimals do not win; the header is the first row with ≥ 2 cells that are not all numbers and whose next row has ≥ 2 concentration-like
cells (so preamble lines are skipped). Concentration column = first header matching
`conc|dose|standard|^std$|level|calibrator|ng/|pg/|ug/|mg/|iu/|mol`, else the first non-bookkeeping column that is all
concentrations. Concentration cells accept numbers, numbers with a unit suffix, and blank words (`blank`, `neg`, `zero`,
`buffer`… → 0). Signal: all replicate-named columns (`Rep 1`, `2`…) when there are several, even beside other numeric columns
(`C line`), else the first column
matching `T/C|ratio`, else `test|signal|intensity|peak|area…`, else the first numeric column. Units come from
`(…)`/`[…]` in the concentration header. Returns `null` for anything else (concentrations-across-the-top tables keep
using §11's paste). `signal` may name several columns separated by commas (`"Rep 1,Rep 2"`). The series gets `cMax` = the highest
concentration. `calwizard import FILE [--conc COL --signal COL[,COL…] --name N]` → `{series, columns, …}`;
`POST /api/import`.

## 22. Variability layers: predict, plan, dial in (v3.0)

The curve (μ(c), σ) describes **one run** (within-run spread). Real assays add sources — lots with slightly different
performance, readers with bias and noise, days, operators. A Series carries `layers` (outermost first), each

```json
{ "name": "Lot", "units": 3, "on": true, "offsetSd": 0, "cv": 0.02, "gainCv": 0.03, "noiseCv": 0.1 }
```

| field | per-unit effect | meaning |
|---|---|---|
| `offsetSd` | a ~ N(0, offsetSd²) | reads a fixed amount high/low (signal units) |
| `cv` | m ~ N(0, cv²) | reads x % high/low everywhere |
| `gainCv` | g ~ N(1, gainCv²) on the signal above the blank | steeper/flatter curve: "performance" |
| `noiseCv` | k ~ N(1, noiseCv²) scaling σ | noisier units |
| `units` | — | how many units an experiment uses |
| `on` | — | counts toward the variability the app uses |

**22.1 Model.** One reading at c from one unit of every layer:
`y = [μ0 + G·(μ(c) − μ0)]·(1 + M) + A + K·σ(c)·ε`, μ0 = μ(0), `G = Π g`, `M = Σ m`, `A = Σ a`, `K = Π k`.
Mean μ(c); variance to first order (exact for the offsets)

`var(c) = σ(c)²·Π_on(1 + noiseCv²) + Σ_on [ (μ(c) − μ0)²·gainCv² + μ(c)²·cv² + offsetSd² ]`.

When any layer is on, `sd_eff(c) = √var(c)` replaces σ(c) **everywhere** (§5 rows, ladder, closeness, recovery,
heat, experiments). No layer on → unchanged. (Equations mode: σ(c) = sd(S) at S = μ(c).)

**22.2 Budget.** `budget(c)` → `{c, mean, total, within, layers: [{name, on, var, share}]}`: `within` = the first
term; each layer's `var` is its own bracket (computed even when off); `share = var / total` for layers that are on,
null when off; `total = within + Σ_on var`. `cumulative()` → for k = 0…L: `{layers: first k names, n}` = §12 headline
ladder length with only the first k layers on (the story "within-run → + Day → + Reader → + Lot").

**22.3 Plan (design-aware experiments).** `simulateDesign(model, concs, n, runs, seed, metric, k, alpha)`: every run
draws, for each layer, `units` independent unit effects (g, m, a, k) — **crossed** design: every combination of one
unit per layer reads every concentration n times (so Π units · n readings per concentration). Random-number order:
for each run, for each layer (outermost first), for each unit: g, m, a, k (four normals, §13 generator); then for
each concentration, for each combination (lexicographic, outermost slowest), for each replicate: ε. Per run and
concentration the pooled readings give mean/SD → §13 rows, significance, pass; plus the **estimated components**
of 22.4 on that run's data. Output = §13 output + `components: [{name, true, Q}]` (per layer and `within`, the run
spread of the estimated variance at the middle concentration, `true` from 22.1).

**22.4 Dial in (real data).** Input: long rows `{c, <layer names…>, y}` (the unit label per layer, any strings).
Per concentration, a **crossed main-effects ANOVA** (method of moments, unweighted unit means, balanced-design
formulas): for each layer L with u_L units, `MS_L` from its unit means; residual `MS_e` from the remainder;
`σ²_L(c) = max(0, (MS_L − MS_e)/(N_c/u_L))`, `σ²_e(c) = MS_e`. Then per layer a non-negative least-squares fit over
concentrations of `σ²_L(c) = offsetSd² + μ(c)²·cv² + (μ(c) − μ0)²·gainCv²` gives the **measured** offsetSd, cv,
gainCv — when the cv and gain columns are nearly collinear across the data (correlation ≥ 0.995, e.g. a small
blank signal) they cannot be told apart: a two-term fit [offset, cv] is used and a note says so. Each layer also
reports `units` and `rough` = the 90% range factor [√(df/χ²₀.₉₅), √(df/χ²₀.₀₅)] (df = units − 1) of an SD estimated
from that many units, with a note below 5 units; `σ²_e(c)` is compared with the predicted within term. Output: `{perConc: [{c, n, within, layers: {name: var}}],
layers: [{name, measured: {offsetSd, cv, gainCv}, predicted: {…}}], notes}`; notes flag unbalanced cells and layers
with < 2 units. **Adopt** copies measured values into the layers (one undo step).

**Headless.** `calwizard budget SERIES [--c C…]` → `{rows, cumulative}`; `calwizard design SERIES [--n N --runs R
--seed S --alpha A]` → 22.3; `calwizard dialin SERIES DATA.csv` → 22.4 (CSV header: `c,<layer names>,y`).
`POST /api/budget`, `/api/design`, `/api/dialin` the same.

**GUI (story flow).** The Budget tab opens with a three-step guide: `1 Predict · 2 Plan · 3 Dial in`. Left panel gets a third step under the curve: **Layers** (Predict) — one compact row per layer
with on/off, name, units and the four sizes as %/SD, add/remove; a one-line summary ("4 resolvable levels within a run
→ 2 with all layers"). Right sidebar gets **Budget** next to Levels | Experiment: stacked bar per level showing each
source's share, the cumulative counts, and a **Dial in** drop zone (paste CSV) showing predicted vs measured with
**Adopt**. The Experiment tab uses the design (units per layer × n) when layers exist.

## 23. Conditions (several curves of the same assay)

A condition is one Series: the same assay measured on another lot, reader, day or site, with its own curve. The
browser keeps several (`series[]` in the store, one active); headless they are simply several Series files.

`compare(models, concs?)` — the first is the reference; `concs` defaults to its levels:
- `conditions[i] = {name, levels, lod, loq}` (headline ladder length and §15 limits, each with its own settings);
- `rows[j] = {c, mean[i], bias[i], readsAs[i], concBias[i]}`: mean signal of each condition, its bias against the
  reference as a fraction of the reference signal, the concentration the reference curve reports for that signal (§6),
  and `(readsAs − c)/c` (null at c = 0 or when out of range);
- `between` (≥ 2 conditions, else null) sizes the spread as one §22 layer: `offsetSd` = SD (n − 1) of the blank means;
  `gainCv` = median over c > 0 of `SD(rise_i(c)) / |mean(rise_i(c))|` with `rise_i(c) = mean_i(c) − mean_i(0)`;
  `units` = the number of conditions.

Headless: `calwizard compare A.json B.json [...] [-c C...]`, `POST /api/compare {series: [...], concs?}`.

GUI (Variability workspace, and the name menu in the top bar): `+ Add a condition` starts one as a copy of the active
series; pasting or importing data then replaces that condition's table. The condition being edited is the reference.
A table lists each condition's levels, LoD, LoQ and the range of `concBias` across the levels; a small chart overlays
the curves; `Use as a layer` adds or updates a layer named `Condition` with the `between` sizes. Adding, switching
and removing conditions are undo steps. Sharing and export act on the active condition.

## 24. Fixed bias and the error budget (tolerance stack)

A layer (§22) may carry a known fixed shift against the calibration: `biasOffset` (signal units) and `biasPct`
(fraction of the signal), e.g. a reader that reads 5% high. Bias changes accuracy, not spread: the model's mean, the
ladder and the limits are unchanged by it.

`tolerance(model, concs?, k?, tea?)` with `Series.tolerance = {tea: 0.3, k: 2}` as defaults. Per concentration, the
sources are the within-run spread and every layer that is on. In signal units each has `bias = biasOffset + biasPct·μ`
(0 for within-run) and `sd = √(its §22.1 variance term)`; dividing by the slope (§15) gives `biasC = bias/slope` and
`sdC = sd/|slope|`. Then
- `bias = Σ biasC`, `sd = √Σ sdC²`;
- `total = |bias| + k·sd` (the usual total-error budget) and `worst = Σ|biasC| + k·Σ sdC` (every source at its limit
  at once: the linear tolerance stack);
- for c > 0: `rel = total/c`, `worstRel = worst/c`, `ok = rel ≤ tea`. Where the curve is flat these are null.

Output `{k, tea, rows, met, total}` (`met`/`total` count the levels with c > 0 that could be judged).
Headless: `calwizard tolerance SERIES [-c C...] [--k K] [--tea T]`, `POST /api/tolerance`.

GUI (Variability workspace): each layer row has a `known bias` line; the **Error budget** section has the allowed total
error and coverage k as scrub fields, one stacked bar per level (bias solid, k·SD lighter, one colour per source, the
limit as a line; bars past three times the limit are clipped) and the numbers `± total · bias · worst`.
